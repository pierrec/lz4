# Changelog

Notable changes to `github.com/pierrec/lz4/v4`, newest first. Entries before
v4.1.34 were reconstructed from the git history; numbers are pull requests or
issues in this repository.

## v4.1.34 (unreleased)

### Fixed

- With concurrency, `Reader.Read` and `Reader.WriteTo` no longer return while
  the read-ahead is still reading the source, and `Reader.Reset` and `WriteTo`
  after a failed write wait until the read-ahead has stopped using the source,
  so the caller may reuse it (#292).
- Concurrent `Reader.WriteTo` recycles its block buffers, including after a
  decode error (#290).

### Changed

- The `purego` build tag now implies `noasm`: `purego` builds on amd64, arm64
  and arm no longer use the assembly decoders and xxHash32 kernels (#283).

### `lz4c`

These ship in the `cmd/lz4c` release that follows this tag.

- `-l` now sets the compression level; it was always `Fast`. Levels above 9 are
  rejected instead of silently falling back to `Fast` (#285).
- Errors go to stderr with exit status 1, instead of to stdout with status 0
  (#288).

### Internal

- The amd64 and arm64 block decoders are generated by `internal/lz4block/_gen`
  (#282).
- `FuzzFrameRoundTrip` covers multi-block frames, `ReadFrom`, `Flush` and
  `OnBlockDone` (#284).
- CI tags the next `lz4c` release when `lz4` is tagged (#281).

## v4.1.33 (2026-10-02)

- `Writer` reports each block to `OnBlockDone` once, before `Close` returns;
  `ReadFrom` used to report twice (#274).
- Legacy frames use buffers sized to the compress bound. Incompressible 8 MB
  blocks no longer produce headers that `lz4` and the Linux kernel stop at, and
  `Reader` accepts the larger blocks `lz4 -l` writes (#276).
- `lz4c` can be installed with `go install`; its module path is now
  `github.com/pierrec/lz4/cmd/lz4c` (#275).
- The `appengine` build tag is gone; use `noasm` or `purego`. `lz4c` requires
  Go 1.22, like the library (#273).
- CI checks the `Writer`'s output with the `lz4` command, and test data records
  its origin and licence (#276, #277).

## v4.1.32 (2026-10-02)

This tag is not on the `v4` branch; everything in it is also in v4.1.33.

- amd64: long overlapping matches are copied with AVX2 when available (#269).
- arm64: long overlapping matches are copied 64 bytes at a time through NEON
  (#268).
- CI tests on the Silesia corpus, the C-compatible compressor is fuzzed against
  C, and the repository gains `AGENTS.md` (#267, #270, #271).
- Repository cleanup, including a committed test binary (#266).

## v4.1.31 (2026-09-27)

This release requires Go 1.22, and `Reader` is stricter about invalid frames.

### Added

- `CCompatFast` and `CompressorCCompat`, a port of `LZ4_compress_fast` whose
  output matches lz4 1.10.0 (#262).
- `ErrInvalidFrameDescriptor` and `ErrInvalidContentSize`.

### Fixed

- `Reader` rejects frames it used to accept: frames truncated at a block
  boundary, before the end mark or content checksum, or right after the
  descriptor; invalid descriptor version or reserved bits; frames with a
  dictionary ID; content that differs from the declared size; and oversized
  blocks read directly into a large buffer (#260).
- A legacy block whose compressed size equals the bytes decoded so far no
  longer ends the stream early (#260).
- `Reader.WriteTo` on an empty source returns nil instead of `io.EOF` (#260).
- `Writer` fails a frame whose data differs from `SizeOption` and rejects
  `Block8Mb` outside legacy frames (#260).
- `CompressorHC.CompressBlock` no longer writes past `len(dst)` when `dst` is
  too short (#260).
- `Reader.WriteTo` no longer stops silently at a later frame with a larger
  block size or without concurrency (#258).

### Performance

- amd64 and arm64 decoders handle long copies faster, and on arm64 dictionary
  copies use 16-byte moves. xxHash32 gains amd64 assembly and pinned loop
  alignment (#265).
- `Compressor` loads without bounds checks on amd64 and arm64; output is
  unchanged (#263).
- `CompressorHC` uses smaller tables and handles single-byte runs in bulk;
  output is unchanged (#259).

### Internal

- Compression benchmarks, golden output digests and comparisons with C (#264).
- Native Go fuzzers replace the go-fuzz harness, with a CI smoke test (#260).

## v4.1.30 (2026-09-15)

- Added `ErrWriterClosed`. `Writer.Close` now closes the `Writer`: a second
  `Close` used to corrupt the stream, and a `Write` after `Close` looped
  forever (#255).
- A block checksum of zero is now written; it used to be skipped (#255).
- Legacy frames no longer leak into the descriptor, which broke later frames
  and wrote block checksums into legacy frames (#255).
- With concurrency, `Reset` after `Close` no longer blocks forever, and `Reset`
  no longer leaks goroutines and buffers from an abandoned read (#255).
- `Reader.WriteTo` writes the remainder of a partly read block (#251).
- Concurrent `Writer.Flush` no longer reuses a buffer still in use (#254).
- `Reader` no longer returns garbage for zero-size frames (#231).
- Non-concurrent `Reader` and `Writer` reuse the frame data block across `Reset`
  (#256).
- amd64 match copies are inlined with splat and tile stores for overlapping
  matches; arm64 has a shorter shortcut path and a prefill for offsets 17 to 31
  (#252).
- CI adds Go 1.27 and drops Go 1.24 (#253).

## v4.1.29 (2026-08-18)

- `XXHZero.Sum32` picks its path from the full length, so content checksums are
  correct for inputs whose length is near a multiple of 4 GiB (#250).
- arm64: match copies tuned for Neoverse cores (#248).

## v4.1.28 (2026-08-05)

- arm64: fast match copy for offsets 3 to 7 (#246).
- xxHash32 gains arm64 assembly (#247).

## v4.1.27 (2026-05-31)

- `Writer.ReadFrom` returns nil instead of `io.EOF` when the source is a whole
  number of blocks, which broke `io.Copy` (#245).
- arm64: fast paths for the decoder's shortcut, short-offset matches and long
  non-overlapping copies (#243).
- CI tests Go 1.24 to 1.26 (#244).

## v4.1.26 (2026-03-06)

- `Reader` no longer copies stale data for a zero-length block, `Writer.Reset`
  returns its buffer to the pool, and `Writer.ReadFrom` skips zero-byte reads
  (#240).

## v4.1.25 (2026-01-17)

- `Reader` returns a bare `io.EOF`, not a wrapped one (#239).

## v4.1.24 (2026-01-16)

- Returning an empty buffer to the block pool no longer panics, and the broken
  tests are fixed (#238).

## v4.1.23 (2025-05-10)

- `Reader` continues into frames concatenated after the first (#229).
- `Reader.WriteTo` works on a `Reader` that has already started (#227).
- `Reader` resets the frame at EOF to release its block buffer (#220).
- Faster `noasm` decoder (#226) and fewer allocations in the block pool (#228).
- Replaced deprecated functions (#230); added CLI benchmarks (#225).

## v4.1.22 (2024-12-12)

- Block checksums are computed on the block, not its source (#223).
